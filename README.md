# Pandora

Pandora 是 Swift 为主的 iOS 双任务工作卡项目。当前 `0.1.0~probe3.4` 是 **工作组模型加「文件」单卡接入的本地草案**，不是有双 App 实时托管界面的产品版本。

- 包名：`com.tsangbaby.pandora`；作者、维护者：Tsangbaby。
- 验证目标是 iPhone 13 Pro / iOS 15.4.1。只接受已在前台的系统备忘录或文件；设置中显式选一个，30 秒内手动返回所选 App，再点挂载。不自动启动或切换 App，不创建第二个 Scene，也不读取文档内容。
- 备忘录保留显示、点击、实际落字及原生归还的验收。文件只验显示、滚动、点击及原生归还，不主动请求键盘焦点。两者不能同时挂载；本草案没有连上真实 A＋B 轮换、并看、拖放或 PiP。

## probe3.4 工作组模型与文件单卡

probe3.3 是已验收的备忘录基线。新的工作组模型区分成员、主任务、槽位、停靠、唯一输入和替换代次；并看还需适配器能力和两边可读空间，不兼容时保持大卡，不把两个状态卡当两路实时内容。模型未接手手机上的会话。

目标机只读检查已在「文件」观察到唯一前台 Scene、既有原生呈现者、图层容器和已加载窗口。新增「准备文件实验」仅在已选 App 前台显示手动面板，面板和挂载绑定同一个现存 Scene；不会仅凭 App 名称或丢失后的旧 ID 再绑定。旧面板失效时按现有清理屏障退出，不改借用窗口。

ARM64 Linux Swift 5.8.1 的 Debug / Release 各实际运行工作组 96 项、键盘 96 项、旧状态／几何 4,774 项，均零失败。控制和设置入口仅做 Swift 语法解析，原生新增夹具仅核对源；未通过 iOS 编译，未出包或装机。文件的实际显示、滚动、点击、结束后恢复均须独立验收，之前不能开启两 App 的大卡轮换或双实时并看。

## 已验收的 probe3.3 键盘基线

用户已确认 probe3.2 正常生效，录屏展示实时文字编辑和中文落字；但键盘初始隐藏、挂载后首次打开时，整张 App 卡片会突然缩小，收起再开会重复。此前把键盘高度从外层可用空间扣除、再 fit 整个 Scene，与当前键盘已经随完整 Scene 同卡呈现的形态冲突。这里是布局策略和状态历史依赖，不是变换工厂再次失败，也没有证据证明 UIKit 内部重复避让。

probe3.3 保留全部已经生效的原生 Scene／变换／窗口／所有权／焦点／清理代码，只调整 Swift 键盘环境与布局：

- 同卡键盘不再驱动整个 App 二次缩放；相同源尺寸、根几何、安全区和面板布局始终得到同一基础卡片比例。键盘通知也不再重复发布相同矩阵。
- 环境观察独立于 session。初始为未知，不伪装隐藏；idle/mounting 也缓存通知，End 不代表键盘被收起。已有键盘若没有新通知仍可能是未知，但正确比例不再依赖是否收到了过去的事件。
- 通知帧不作为卡外遮挡证据，不强制收放键盘或结束中文 marked text。只在已经拥有 Scene 后，从既有 UIKit 输入宿主的可见填充子视图取得有限正向证据；仅接受不同、同屏同 Scene、严格更高层窗口。坐标经 UIWindow 桥接，避免跨窗 UIView 直接换算；空包装器、同级或顺序不明、透明／旋转缩放／不可读的形态不声称已识别。
- 若这种独立正向证据确实与卡片重叠，按原来的自身清理路径结束实验、交还原生，不缩到不可输入、不抢回焦点。局部只读扫描有边界；**它不能发现所有远程进程的键盘或保证所有第三方键盘兼容**。即使局部扫描为空也不标成“系统无键盘”。输入行仍被遮挡时应结束并在原生中继续，不能把裁切、缩小或源码测试冒充响应式重排。

此修正不表示长笔记光标、所有输入法、真正 WindowServer 外部遮挡、关闭后的原生编辑和生命周期／性能已验收。正式 A+B、横竖屏并看、拖放与 PiP 仍是后续关卡。

## 历史变换修正与已知边界

probe1 在 Scene 查询失败；probe2 修复查询后，真机在单内容层限制处停止。probe3 用原生 Presenter 替换后，在真机上下文更新阶段仍失败，用户截图显示“原生上下文更新异常，需撤销实验”。错误发生于激活前；当时 catch 隐去了异常细节，失败后的 Notes owner 只读核对因 Minis 前台保护停止，不能声称交还已验证。

probe3.1 已由用户实际尝试并失败，提示“原生工厂未返回 UITransformer。”；此前“子类 receiver 会使工厂创建子类”的推断错误。目标机器码显示该工厂固定分配 `UITransform`，换调用类不能改变它。截图只表示 nil/类型保护未通过，不能确定 probe3 原异常的唯一抛出点。旧 probe3/probe3.1 不再推荐测试。

在用户另行批准的目标 iOS15.4.1 隔离数据对象测试中，`UIMutableTransformer` 加入基础仿射变换后，类型和矩阵正确；直接复制该变换会使矩阵回到 identity。随后独立**上下文**闭环实际运行18项全过：不预先复制变换，将构造完成的组合对象存入原生上下文，经过上下文 copy/mutableCopy 后读回的六系数仍正确，替换新值不改变旧上下文。这个结论仅适用于该已取证目标路径，不代表 Scene 或输入通过。

probe3.2 按这条实测路径构造：每次创建新的组合对象，加入基础变换，校验全部六系数，发布后不再修改该对象，也不 freeze-copy 它；存入可变上下文与 Presenter 复制后的上下文均再次校验类型和矩阵。原来的同窗托管、所有权、手动输入及自身清理屏障保持不变。仍须实际显示／触摸／落字／原生交还验收，不能把18项对象测试或构建通过当成完整修复。

## 未来装机验收（草案未构建）

已验收的 probe3.3 继续保留。文件单卡草案须先通过 Mac 构建与回归；若之后交付该测试包，使用非敏感的本地测试文件夹并保持竖屏。选择「准备文件实验」，切到「浏览」，只挂载一次；验证画面实时、滚动和点击正确，再结束和关闭，在原生文件中继续操作。不要使用移动、删除或搜索作为首轮测试。

以下保留备忘录的原验收步骤：

1. 保存当前工作，由包管理器安装 **RootHide** 版；按包管理器提示手动重载 SpringBoard。这个版本没有安装脚本。先在备忘录准备一篇**无隐私内容**、足够长用于滚动和底部光标的测试笔记，保持竖屏。
2. 先测键盘收起时准备／挂载，再点正文或请求输入呼出键盘；核对卡片没有缩成小卡。收起再开、展开候选栏，尺寸应保持可读，当前输入行／候选／选区应可见。通过后再测键盘已打开时准备／挂载，最终尺寸应与前者一致。
3. 记录是否出现同一篇笔记，以及在卡片内滚动、点击是否命中正确位置。**黑屏、静止、点不动、输入行被遮住不是通过。** 出现任一情况先结束，不继续请求输入；不强制收放键盘重复撞错。
4. 若触摸正确，点「请求输入」后点卡片正文，输入一小段可丢弃的文字（例如 `P33-试`），检查中文组合、候选切换和实际落字。键盘弹出或状态文字变化都不等于通过。
5. 保持键盘打开时点「结束实验」，再点「关闭」。在原生笔记中继续滚动、输入几个字并确认先前文字保留，完成真实交还闭环；任一异常停止。原生交还和键盘小闭环通过后再另测离开／锁屏／方向退出，不把这版实验当成 A+B 已完成。

若无面板，不认定安装成功或托管成功；记录停在哪一步。「设置 → Pandora → 停止实验／取消准备」可撤销准备。若系统界面异常，停止使用并在包管理器中卸载 Pandora，再按提示手动重载。该包不用于日常工作。

## 构建

使用官方 [RootHide Theos](https://github.com/roothide/theos)（固定 `958fea4f779943505b15b93c88bb4db8d97b346d`，递归初始化子模块）与 Xcode 16.4 的 iPhoneOS SDK。Mac 上需 GNU Make、`dpkg-deb`、`ldid`。设置 `THEOS` 后运行 `bash scripts/build_roothide.sh`。CI 仅构建并验包，不连接、安装或重启手机。

Swift 状态测试、Objective-C ABI 反例和 `.deb` 检查只能证明相应测试和构建门槛，不能证明真机交互或帧率。本实验包没有加入自定义转场；动画流畅性将在正式转场落地后单独按目标真机验收。
